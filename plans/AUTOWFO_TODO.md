### Phase 17: Re-run Correctness + Top10 Accuracy (AWF-106 ~ AWF-108 + AWF-106b patch)
> Goal: Fix two structural correctness bugs discovered via production observation: seen_keys are always invalidated on re-run (costing full re-evaluation every time), and Top10 display shows only the latest run's results instead of the historical best.
- **Root cause of seen_keys invalidation (AWF-106)**: `data_end` in `combo_key` changes on every run because `_load_or_update_symbol()` always appends fresh OHLCV candles → `data_end` advances by one or more candles → all 15,250 seen_keys from the previous run have old `data_end` → none match → 0 skips → full re-evaluation. Fix: split into `stripped_seen_keys` (without `data_start`/`data_end`) for skip decisions, and keep `full_seen_keys` for artifact tracking.
- **AWF-106b patch (null-field defaults)**: After AWF-106, production observation showed second run STILL took identical time. Root cause: `capital_mode`/`wf_valid_days`/`wf_mode` are in `strict_config_fields` but were added after 87,519 CSV rows were written → all old rows have NaN in those fields → `has_all_config_fields_fn` returns False for every row → `seen_keys` always empty set → 0 cross-run skips. The 22,320 visible "skips" were intra-run `planned_keys` dedup only. Fix: `_SEEN_KEY_NULL_FIELD_DEFAULTS` dict + fill None/NaN before filter in `_build_seen_keys`.
- **AWF-106c patch (int/float key normalization)**: After AWF-106b, second run STILL showed 22,320 skips. Root cause: pandas upcasts integer columns with ANY NaN rows to float64; `_normalize_key_value(0.0)` returned `0.0` (string `"0.0"`) while `_normalize_key_value(0)` returned `0` (string `"0"`). AWF-106b correctly let old rows pass the filter but then their combo keys contained `"wf_valid_days=0.0"` while current-run keys contained `"wf_valid_days=0"` → never matched. Fix: in `_normalize_key_value`, integer-valued floats (`0.0 == int(0.0)`) are converted to int for consistent key representation.
- **Root cause of Top10 staleness (AWF-107)**: `_get_results_payload()` reads `param_sweep_top10_{latest_run_id}.csv` (sorted by mtime) as primary source; fallback to `_pick_top10(combo["rows"])` only triggers when the latest file is empty. Fix: promote `_pick_top10(combo["rows"])` from full combo_summary.csv to primary; expose latest-run top10 as a separate secondary key for UI toggle.
- AWF-108: Performance micro-opts — progress emit throttle, seen-key rebuild vectorization, configurable checkpoint frequency.
- Prerequisite: Phase 16 complete (AWF-105 done).
- Exit criteria: second run with identical config skips all prior combos; Results Top10 defaults to all-time best; performance micro-opts applied and tested.
